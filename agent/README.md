# Agent 使用协议

本项目是供编程 Agent 读取的前端参考库。浏览页面用于人工查看效果和审核方向，资源选择、适配与实现由调用方 Agent 执行。目录和 CLI 不调用模型、不生成业务代码。

## 最短路径

在仓库根目录使用 Node.js 18 或更高版本，无需安装 npm 依赖：

```sh
npm run agent:check
node scripts/agent-catalog.mjs list --query "按钮" --kind effect --limit 5
node scripts/agent-catalog.mjs list --place 按钮 --goal 交互反馈
node scripts/agent-catalog.mjs show effect:magnetic-btn
```

全部输出为 JSON；失败返回非零退出码和 JSON 错误。目录过期时先运行 `npm run agent:build`。直接读取 `agent/catalog.json` 前同样需要 check。命令路径相对仓库根目录，项目复制或更换目录后仍有效。视频原项目仍需网络。

`list` 默认返回最多 20 条及总数，支持 `--limit`；关键词按空格分词，要求全部匹配。`--place`、`--goal`、`--project` 精确匹配已有场景标签。没有匹配不能解释为资源不存在：当前只有部分效果标注场景，可以移除场景条件改用关键词查询。排序沿用原清单，不是质量排名。

## 资源含义与证据

| 字段 | Agent 应如何使用 |
| --- | --- |
| `id` | 稳定、带类型前缀的引用；在实施方案中保留 |
| `source` / `integration.readBeforeUse` | 打开完整本地源文件；路径相对仓库根目录 |
| `preview` | 相对本地服务的人工预览链接 |
| `scenes` | 已有人工场景标签；null 表示没有依据，不代表不支持 |
| `declaredDependencies` | 原条目声明；实际运行依赖需核对 init、引擎和目标环境 |
| `verification` | unknown/unverified 不能写成已支持或已测试 |
| `fingerprints` | 生成时本地输入文件的 SHA-256，供索引新鲜度检查 |

- `effect` / `demo-module`：可在图鉴舞台运行的演示。`code` 是摘录，可能缺 HTML、样式和清理；完整 `init` 也可能只适合固定舞台。
- `skill` / `method-document`：方法文档，先核对工具和依赖；阅读文件不代表已经完成其流程。
- `video` / `remote-reference`：本地只有索引，先访问上游源码才能移植，离线时明确缺失依据。
- `recipe` / `runnable-example`：含独立示例、槽位和效果引用的组合配方。`schema-checked` 仅表示资源引用、槽位和属性冲突经过静态检查；浏览器、移动端和无障碍验证状态分别列出。
- `coverage.verifiedTemplates` 当前为 0。效果能独立展示，不证明能安全拼成页面。没有记录的许可证结论需要回到原始来源核对。

## 从业务到实施

### 1. 澄清需求（grill me）

以 `agent/brief.example.json` 为需求单格式。首先确定使用者、主要任务、成功标准、设备和目标项目技术。每轮只问 1–2 个会改变选型的问题；每个问题说明它影响的决定。不要让人选择尚未解释的技术名词。

只有会阻止实施或导致返工的未知项才阻塞实施。例如接入已有项目时技术栈未知，应先读取项目；核心业务流程不清楚，应询问人类。色彩、圆角等低影响细节可以写成可撤回的假设，记录到 assumptions。持续更新需求单，避免重复询问已有答案。此阶段由调用方 Agent 根据协议对话，CLI 不提供对话模型。

### 2. 先约束，再检索

从主要操作和页面位置查询，不从“炫酷”“高级”等模糊形容词直接推导效果。读取候选完整源码及相关技能；每个候选写出资源 ID、支持它的证据、适配成本和仍未知的能力。最多给出一个主方案和两个有实际取舍的替代方案。证据不足则缩小实现范围或先制作验证样例，不编造置信度分数。

### 3. 组合规划（变形金刚方向）

当前提供一个可运行的列表组合样例，还没有通用模板组装器。通过 `node scripts/agent-catalog.mjs list --kind recipe` 查找配方，再用 `show recipe:project-list` 查看槽位、效果引用、可调参数、数据契约和源文件。参数通过示例 CSS 变量配置；接入真实业务时需自行实现空结果、错误和请求取消。Agent 可以据此编写组合方案，但应将整页组合标记为未经验证。一个方案至少包含：

- 布局槽位与资源 ID，例如首屏、列表、按钮；动效服务于哪个业务操作。
- 各效果所属 DOM 元素，谁控制 transform、opacity、滚动和焦点；同一属性有多个控制者时使用外层包装或只保留一个效果。
- CSS 作用域、唯一 ID、资源生命周期、destroy 清理与依赖加载方式。
- 触屏替代行为、键盘可操作性、减少动态效果时的静态表现、错误和加载状态。
- 动态背景与前景对比、多个动画并行时的实际性能验证。

后续模板应独立收录为具备槽位、参数、样式 token、兼容约束、完整可运行源码与验证记录的资源。只有实际通过验证的模板和组合才能宣称可直接落地；不能根据原子数量推算模板能力。

### 4. 实施与交付

Agent 把需求单、资源 ID、源码位置、适配说明和验收项写入目标项目的实施方案，再实际修改项目。已有授权范围内自主完成；只有重大目标冲突或关键需求缺失时才继续追问。

交付时给出可运行页面、采用资源及改动、验证结果、未验证项。至少核对主流程、目标视口、键盘/焦点、减少动态效果、卸载清理；未执行的检查如实标注。人类主要审核整体参考与业务结果。

## 维护

沿用 `src/registry.js`、`src/skills-data.js`、`src/video-data.js` 作为内容清单。新增效果按现有规则编写模块；场景依据写入 `src/scenes.js` 或效果的 scenes 字段。随后执行：

```sh
npm run agent:build
npm run agent:check
npm run agent:test
```

提交或复制时包含生成的 `agent/catalog.json`。check 验证本地目录一致性和文件存在，不等于浏览器测试、远程链接检查或组合兼容性验证。
