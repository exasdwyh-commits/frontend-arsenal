# Vantage 设计体系提炼：给受限设备做一套像样的界面

> 上游：[anothaDev/luci-theme-vantage](https://github.com/anothaDev/luci-theme-vantage)（GPL-3.0-or-later）
> 原文规格见 `vantage-spec.md`，主题契约见 `vantage-luci-contract.md`，实现见 `vendor/vantage/`。
> 这篇是**提炼**：把一个真实生产级界面系统的做法，翻译成可复用的方法。

---

## §0 · 前提：先承认约束，再谈设计

这个项目最难的地方不是画得好，是**目标机器很差**：128 MB 内存的路由器，
浏览器是路由器自带的 Web 服务器，没有 CDN、没有网络字体、没有框架、首屏必须 1 秒内。

大多数「好看的界面」在这三条里每一条都直接出局。所以它的设计顺序是反的：

> **先定性能预算 → 再定信息架构 → 最后才是视觉。**

这不是风格选择，是筛选器。任何撑不住预算的想法，在第一轮就被砍掉。

---

## §1 · 性能预算要写成数字，不是形容词

它把"轻"翻译成了可验证的条款：

| 预算 | 数字 |
|---|---|
| 首屏 | < 1 s（设备自己的 web 服务器上） |
| 依赖 | 零 CDN、零 web font、零框架 |
| 内存 | 目标设备 128 MB |
| 降级 | 缺失数据不能让界面卡住 |

**可迁移的做法**：给自己的项目也写一份这样的表，四个数字即可。写不出来，
说明性能还没进入设计阶段——那后面所有优化都是返工。

**坑**：预算写在文档里没人看。要让它真的生效，得进 CI：
它把**模板与 DOM 的安全检查放进了 CI**，同理，性能也可以变成 CI 里的一条断言
（比如首屏资源字节数上限），而不是靠人自觉。

---

## §2 · 降级策略要在写数据层的时候定

做设备管理界面，最容易犯的错是假设数据总是齐全。

现实里：一台 AP 可能没有 DHCP 服务、温度传感器缺某个值、型号字符串是占位符。
上游的做法是**在数据层就把"缺失"表达出来**，而不是在渲染层判空：

- 占位符型号（`Qualcomm...` 之类）要被识别为"这不是真型号"，界面改显示板名；
- 缺失的噪声值不画图，也不画 0——**画 0 是撒谎**；
- 可选依赖（反向 DNS、mDNS、hostapd 的 ubus 对象）缺失时**功能降级而不是报错**。

**可迁移的做法**：给每个字段定义三态——有值 / 明确无值 / 未知未到。
UI 对三态有三种表现，缺省是"未知未到"（不显示），而不是"显示为 0"。

## §3 · 暗亮双主题：切换发生在 CSS 之前

它的主题切换（auto / light / dark）有一个容易被忽略的细节：

> 主题在 `<head>` 里、**CSS 之前**就写进 `<html data-darkmode>`，
> 所以切换**不会闪白**。

配套的三条约束值得抄：

1. **主题存在路由器上，不在浏览器上** —— 全设备一致；没有权限的会话就只存在本地 `localStorage`；
2. **保存的队列只写最后一次** —— 并发保存时中间态直接丢弃，不排队；
3. **切换按钮的循环顺序是"系统没有的那个"** —— 点一下就一定能看到变化，
   而不是"自动 → 亮 → 暗"里可能停在当前看不出区别的那个。

**可迁移的做法**：主题状态永远在文档根元素上（`data-theme` / `data-darkmode`），
任何组件都读它，不要各自存一份；主题相关的 CSS 变量只定义在 `:root[data-theme=x]` 下。

## §4 · 命令面板：把"找页面"从导航成本里拿掉

它的导航是「图标轨（56 px）+ 悬停弹出 + Ctrl+K 命令面板」。

命令面板的实现要点（它注册了 `ui.menu` 的全部页面，最近访问优先）：

- 快捷键 **`Ctrl+K` 或 `/`**——两个都支持，因为 `/` 在浏览器里不冲突，而 `Ctrl+K` 是肌肉记忆；
- 模糊匹配，**最近访问的排前面**（频率比字母序有用）；
- 后续 app 把实体（客户端、接口、无线）也注册进同一个面板——**一个搜索框统治所有对象**。

**可迁移的做法**：全局搜索做成"菜单 + 实体"的统一索引，
而不是每个模块各有一个搜索框。快捷键至少给两个（`/` 与 `Ctrl+K`），
并且**永远把最近用的排在前面**。

## §5 · 顶栏的"空间不够时谁先让路"

这个细节做得很成熟，值得单独拎出来：

> 空间不够时，**主机芯片先让**；到 900 px 以下，指示器胶囊缩小
> （自动刷新胶囊变成播放/暂停图标，未保存计数胶囊只留数字）；
> **面包屑最后才被截断**。

这是一条明确的**优先级序列**：主机信息 → 状态指示 → 导航路径。
它还规定了一个例外：「只重复前一个的面包屑」（"系统 → 系统"）只显示一次。

**可迁移的做法**：给顶栏写一条"谁先被牺牲"的顺序，并在实现里真的按这个顺序降级。
没有这条顺序，响应式就会变成"所有东西一起缩小"，最后谁都看不清。

## §6 · 状态指示：一个脉冲点承担三种语义

它把刷新状态压缩成一个点：

| 状态 | 表现 |
|---|---|
| 正在刷新 | 慢而柔的呼吸环 |
| 已暂停 | 静止 |
| 仪表盘报问题 | 变快 + 琥珀色（重连/告警）/ 红色（错误） |

**可迁移的做法**：一个状态点最多承载三档信息，且**用速度表示"进行中"、用颜色表示"有问题"**——
两个通道正交，不要用同一个视觉通道表达两种状态。

## §7 · 契约：区分"承重"与"装饰"

`vantage-luci-contract.md` 是整份文档里最值钱的部分。它的视角是：
**核心（LuCI）期望主题做什么，以及主题在哪些地方是承重的、哪些只是装饰。**

几条关键结论：

- **渲染顺序**是契约的一部分：主题头 → 核心 `luci.js` → 页面体 → 核心尾 → 主题尾。
  中间任何一步插入自己的东西都可能破坏后续。
- 主题头**必须**在 `cbi.js` 之前加载 `luci.js`，否则 `luci-loaded` 事件永不触发，
  **每个视图都会永远转圈**——这类错误不报错，只是静默卡死。
- 主题头必须提供 `#indicators` 并**保持 `#maincontent` 打开**（保存/重置与通知需要它），
  且**不要输出 `#view`**（那是核心的事）。
- 错误页（404 / CSRF token 页）**也使用主题**——**包括未登录的访客**。

**可迁移的做法**：给任何一个"别人的系统 + 你的皮肤"的组合，
先写一份契约文档：渲染顺序、必须提供的挂载点、谁负责什么、错误路径怎么走。
写完再写代码，能省掉大量"只在特定页面才炸"的问题。

## §8 · CSS：三套主题并行，靠令牌而不是靠覆盖

它同时维护 graphite（暗）/ paper（亮）/ app（应用）三套主题，共 267 KB CSS。
可行的前提是**结构与表现分离**：

- 结构类名（布局、栅格、间距）与主题类名（颜色、阴影、圆角）不混写；
- 主题差异集中在**令牌层**，组件只消费令牌；
- 亮暗两套不靠"在亮色基础上覆盖暗色"，而是**各自完整定义令牌**，
  避免暗色里残留亮色的硬编码色值。

**可迁移的做法**：先定令牌清单再写组件。令牌清单一旦定下，
新增一套主题（比如"高对比度"或"嵌入模式"）的成本才是可控的。

---

## §9 · 安全的做法：把检查放进 CI，而不是放进自觉

它对模板与 DOM 做安全检查并**放在 CI 里跑**：

- 模板里只传**白名单里的值**，不传任意用户输入；
- DOM 写入走受控接口，不拼 HTML 字符串；
- 权限用 rpcd ACL 精确到"只能改自己的那份配置"，且**回滚未完成时拒绝 commit 与 revert 两者**。

**可迁移的做法**：把"模板变量必须转义""不允许 innerHTML 拼字符串"
写成一条能在 CI 里失败的规则，而不是写进 code review 的注意事项里。

---

## §10 · 收束：这个项目值得抄的五件事

1. **性能预算写成四个数字**，并且能进 CI；
2. **数据三态**（有值 / 明确无值 / 未知），缺失不画成 0；
3. **主题状态只在文档根元素上**，切换发生在 CSS 之前，不闪白；
4. **一个全局搜索统治所有对象**，最近使用优先；
5. **先写契约再写代码**：渲染顺序、挂载点、错误路径、权限边界。

以及一条元教训：

> 好界面不是"在好机器上做出来的"，是在**明确的约束下被逼出来的**。
> 约束写清楚了，好看是结果；约束没写清楚，好看只是运气。
